# หน้าจัดการ + theme Payment Recon — design (2026-10-26)

สถานะ: เขียนจากคำขอของผู้ใช้ "ทำหน้าจัดการต่าง ๆ เพิ่ม เช่นการเพิ่มช่อง หน้ารายละเอียดอื่น ๆ ตามไฟล์ xls และใช้ theme ให้เหมือน
https://payment-recon-api.jbac.workers.dev/ เผื่ออนาคตจะเชื่อมระบบเข้าหากัน" (พร้อมภาพหน้าจอ Payment Recon หน้า ฝาก-ถอน)
ผู้ใช้ไม่ได้อยู่ตอบคำถามระหว่างทำ — ข้อที่ระบุว่า *(ตัดสินใจเอง)* คือการเลือกของผู้สร้าง แก้ได้ภายหลัง

## เจตนา / ทำไม
- ทีมต้องแก้ข้อมูลสัญญา/ช่องได้เองจากหน้าเว็บ (เพิ่มช่อง เปลี่ยนลิงก์ หยุดสัญญา คืนเงิน ติดตาม ใส่ Reg รายเดือน)
  โดยไม่ต้องแก้ Excel แล้ว import ใหม่ทุกครั้ง — และข้อมูลที่แก้ด้วยมือต้อง **ไม่ถูก import ทับ**
- หน้าตาต้องเป็นชุดเดียวกับ Payment Recon (ระบบพี่น้องของบริษัท) เพื่อให้รวมกันในอนาคตได้โดยไม่สะดุดตา

## เป้าหมาย
1. Theme = โทเคน/ฟอนต์/โครงหน้าจอของ Payment Recon: sidebar 220px โลโก้ไล่สี `linear-gradient(135deg,#f2568c,#8b5cf6)`,
   topbar 50px (hamburger · ชื่อหน้า · ภาษา · ปุ่ม Light/Dark · ผู้ใช้ · ออกจากระบบ), การ์ด KPI ไล่สี มุม 14px, panel ขาวเงา
   `0 8px 22px rgba(88,98,148,.12)`, ฟอนต์ Poppins + IBM Plex Sans Thai + IBM Plex Mono (ตัวเลข), โหมดมืดโทน indigo
   (`#171b2e / #1e2342`), สลับด้วย `data-theme` บน `<html>` จำใน `localStorage.adm_theme` (ชื่อเดียวกับ Recon)
2. หน้าจัดการ (server-rendered form, ไม่มี SPA) ครอบคลุมทุกชีตของ `Platinum Marketing Plan.xlsx`:
   - **สัญญา** (ชีต roster รายเดือน): รายการ ค้นหา กรอง · เพิ่ม/แก้ · แนบ/ถอดช่อง · เพิ่มช่องจาก URL ในหน้าเดียว
   - **ช่อง**: รายการทุกช่อง (ประเภท ตัวเก็บ สมาชิก ตาย ตรวจล่าสุด error) · เพิ่ม/แก้ · ฟื้นสถานะตาย · ย้ายลิงก์ (บันทึก alias เดิม)
   - **Reg รายเดือน** (ชีต Reg List + คอลัมน์ Reg): ตารางสัญญา × เดือน กรอกทีเดียวบันทึกทีเดียว
   - **หยุด / คืนเงิน / ติดตาม / แทนที่** (ชีต Stop list, Refund ch, Follow Up ch, Substitute ch, Stop Ch): บันทึกเหตุการณ์
     พร้อมวันที่ ยอดเงิน หมายเหตุ และเปลี่ยนสถานะสัญญาให้สอดคล้อง (stop→stopped, refund→refund, อื่น→หมายเหตุ)
   - **รายงานรายเดือน**: สรุปต่อเดือน (จำนวนสัญญา ยอดจ่าย reg รวม ช่องสาธารณะ/ส่วนตัว) + ตาราง สัญญา × วัน ของเดือนที่เลือก
     (สีตามสถานะ กดช่องไปหน้าหลักฐาน) แบบเดียวกับตารางปิดยอด "เว็บ × วัน" ใน Recon
   - **นำเข้า/ส่งออก**: อัปโหลด seed + probe ผ่านฟอร์ม · ส่งออก CSV ช่วงวันที่ · ปุ่มสั่งเก็บข้อมูล/ประมวลผล
   - **ตั้งค่าและสถานะ**: ค่าตั้ง (ซ่อน secret) · งาน scheduler และรอบถัดไป · run ล่าสุด · สุขภาพ · log การแก้ไขล่าสุด
3. ทุกหน้า 3 ภาษา (ไทย/English/မြန်မာ) ผ่าน `app/i18n.py` เหมือนเดิม; มือถือใช้ได้ (sidebar เป็น drawer)

## ไม่ทำรอบนี้ (non-goals)
- ระบบผู้ใช้หลายคน/สิทธิ์ (ยัง HTTP Basic ผู้ใช้เดียว; "ออกจากระบบ" = ตอบ 401 ให้เบราว์เซอร์ลืมรหัส)
- SSO/การเชื่อม API กับ Payment Recon จริง (เตรียมแค่หน้าตาและชื่อ localStorage ให้ตรงกัน)
- แก้ไขโพสต์/ผลตรวจรายวันด้วยมือ (ผลตรวจมาจากกติกาเท่านั้น)

## สิ่งที่ต้องไม่พัง (anti-goals)
- import ซ้ำต้องไม่ทับแถวที่ติดธง `manual_locked` (สัญญา/ช่องที่แก้ด้วยมือ)
- ฟอร์ม POST ต้องกัน CSRF (Basic auth ถูกส่งอัตโนมัติ): double-submit cookie `csrf` + ตรวจ `Origin` ถ้ามี
- หน้ารวม/หน้าสัญญาเดิมและเทสต์ 101 รายการยังผ่าน; ไม่มี key แปลหลุดในทุกหน้า 3 ภาษา

## ข้อตัดสินใจ
- URL: หน้า HTML จัดการอยู่ใต้ `/manage/...`, รายงานใต้ `/reports/...`; JSON เดิม `/admin/...` คงไว้ให้สคริปต์ *(ตัดสินใจเอง)*
- โหมดเริ่มต้น = สว่าง (ตามภาพที่ผู้ใช้ส่ง) และจำค่าที่ผู้ใช้สลับ *(ตัดสินใจเอง)*
- ไอคอนเมนู sidebar ใช้อีโมจิแบบเดียวกับ Recon เพื่อความเหมือน; ไอคอนสถานะในข้อมูลยังเป็น SVG *(ตัดสินใจเอง)*
- migration `0002_manage.sql`: `contracts.manual_locked`, `contracts.note`, `channels.manual_locked`, `channels.note`,
  ตาราง `admin_log(id, at, user, action, target, detail)`; importer ข้ามแถว locked
- รหัสสัญญาที่สร้างจากหน้าเว็บ = `YYYY-MM-mNNN` (m = manual) กันชนกับ `rNNN` จากชีต *(ตัดสินใจเอง)*
- เพิ่มช่องจาก URL ใช้ตัวแยกประเภทเดียวกับ extractor (`t.me/+hash`, `joinchat/`, `t.me/<user>`, `t.me/s/<user>`, `@user`)
  ย้ายมาไว้ใน `app/links.py` เพื่อไม่ให้ service พึ่ง `tools/`
- ข้อความ flash หลังบันทึก = cookie อายุสั้น อ่านครั้งเดียว *(ตัดสินใจเอง)*
